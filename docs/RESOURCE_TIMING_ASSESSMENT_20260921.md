## Actual concurrency experiment

Selected 24 intact retained development frames, excluding corrupt/incomplete input
records explicitly. Repeated them four times per trial (96 tasks). Each task used
existing checksum/decode, image standard deviation and four palette-mask operations.
Files were warmed once; worker counts rotated across three trials each. Process
pool startup is included. Workers inherited nice 19 with numerical library thread
counts limited to one. Outputs matched exactly across all trials.

| Workers | Median seconds / 96 tasks | Speedup |
| --- | ---: | ---: |
| 1 | 1.492 | 1.00x |
| 2 | .757 | 1.97x |
| 4 | .397 | 3.76x |

This is a warm-cache offline image-processing proxy, not complete review-package
generation, cold-storage throughput, simulator concurrency or human review speed.
No production executor has been switched to concurrent simulation.

## Recommended scheduling and revised outlook

1. Use up to four low-priority workers for separable offline image checks, with
   resource checks and deterministic output merging. The measured speedup applies
   to that component only, not the full project.
2. Overlap offline preparation with another project's live simulation where
   monitoring permits. Never modify or terminate the other project's processes.
3. Keep R3 simulation serial. Current GPU occupancy and the global execution lock
   do not justify a concurrent-Gazebo trial. A future trial requires explicit
   isolated domains/partitions, owned cleanup, protocol compatibility and lower GPU
   contention; do not bypass the lock to test it.
4. Reuse approved assets and retained evidence where scientifically valid. Do not
   eliminate reviews, change observations, or reuse disallowed labels to save time.
5. Budget storage before any new capture wave. Do not clean old evidence implicitly.

Stage 1 remains roughly 1–2 working days of active feasibility/design work: CPU
headroom does not resolve the scientific distribution/coverage question. Stage 2,
if comparable to a <=560-capture wave without substantial redesign, can reasonably
be planned as 1–2 working days of active collection/QA/packaging, with roughly 4–6
hours allocated to serial captures. This is conditional planning, not a deadline.
Combined: approximately 2–4 active working days, plus approvals, human review and
GPU scheduling delays. The exact new budget must be fixed in Stage 1; sufficient
calibration coverage is not guaranteed. No background execution is promised.
